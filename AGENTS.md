# Shared book production workflow

These instructions apply to every book, language and writing session in this repository, including work under `content/` and `writing/`. Read [tools/studio/QUALITY.md](tools/studio/QUALITY.md) before authoring, encoding, repairing, registering or publishing chapters. Book-specific guides add literary, language and research requirements; they do not replace the shared publication checks.

Use this order: read canon/checkpoint → draft → separate editorial review and revision → encode → validate → preview in the actual reader → record a content-bound QA receipt → checkpoint → publish through the gated Pages workflow → verify the live result. A requested batch size never excuses skipped reviews. Reviews are agent work; do not repeatedly ask the user to approve routine chapters or impose artificial waiting periods.

Do model work yourself; do not call a model API for writing or glossing. For Chinese also read `tools/studio/AGENTS.md` and its skills. Use the language's established encoder/helpers; do not apply Chinese romanization or word rules to French. Never rewrite existing story content without authorization. Preserve unrelated work from other sessions. Keep plot details and private review notes out of public receipts and user-facing status updates.

No direct/legacy Pages publishing. Run the shared QA check before pushing; the GitHub Pages workflow checks again against the last deployed release, not merely the previous commit. Missing, incomplete or stale reviews block deployment. Content edits after review require a fresh receipt and preview.
