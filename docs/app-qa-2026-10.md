## 1. Ground rules

**Codebase.**
- `app/` is a vanilla-JS PWA: ES modules, no build step, no framework. Most work happens in `app/js/*.js`, `app/styles.css` and `app/index.html`.
- `content/` holds the books (`library.json` + `books/<id>/ch-N.json`). The chapter format is described in `tools/studio/QUALITY.md`.
- Persistent data lives in IndexedDB (`app/js/db.js`, DB_VERSION 4). The stores are:
  - books, chapters, progress, library, vault, feedback;
  - settings, which also holds the `activity` record.

**Running it locally.**
1. Serve the repo root: `python3 -m http.server 8786`.
2. Open `http://localhost:8786/app/index.html`.
3. Emulate a 375×812 phone viewport.
4. After changing a module, hard-reload, and unregister the service worker if needed.

**Versioning.** Bump `APP_VERSION` in `app/js/version.js` and `SHELL_CACHE` in `app/sw.js` together, to one above whatever HEAD has. Several agents commit here. Any new module, vendor file or data file must also be added to `SHELL_FILES` in `sw.js`.

**Deploying.** The only publisher is the gated **Review and publish reader** workflow (`.github/workflows/publish-reader.yml` + `tools/qa/release.py`). Follow `AGENTS.md` and `tools/studio/QUALITY.md`. Receipts bind to renderer bytes, so reader code changes (R1, R2, R4, R5, R6) may need receipts refreshed. Handle that within the gate's rules; don't bypass it.

**Scope discipline.**
- Commit per batch or per item group, staging only your files. `library.json` often has other sessions' uncommitted edits.
- Don't rewrite story content.
- Never put secrets in the repo, in logs, or in backups.

**Verify every fix in the running app at phone width before marking it done.** "Done" means observed working, not just written.

## 3. Work plan (do in this order)

### Batch 1: correctness and data safety

#### R1 — English piles under the first line of a wrapped sentence *(owner report #2)*
- **Files:** `app/js/reader.js` (`renderPageInto` ~L600–720: the per-line English cut; `findChunkPositions` ~L99–161; `buildEnglishCoverage` ~L232–303).
- **Cause:** for each visual line, `cut = max(eEnd)` of that pair's chunks on the line. Chinese reorders words, so one chunk whose English sits at the end of the sentence (e.g. 过 = "you've") drags the whole translation onto line 1. Later lines then get nothing, or just ".". Chunks whose English can't be located (`eEnd -1`) are ignored. "you" also matches inside "you've" because `'` counts as a word boundary.
- **Repro:** `embers-beneath-the-mountains` ch-9, pair 142.
- **Fix — best-split cut:**
  - At each line boundary within a pair, choose one forward-only cut among the English word boundaries at or after the cursor.
  - Minimise: English characters of earlier-line chunks falling after the cut, plus later-line chunks falling before it.
  - Break ties by the share of the pair's target characters already shown.
  - The pair's last line takes the remainder.
  - Treat a pair as continuing onto a line if any of its target text (not only chunks) is there.
  - Simulated on real data, this drops lines without English from about 10% to 0.6% in Embers and 1.3% in Left Hand.
- **Acceptance:** run the orphan-line counter in section 6 on Embers ch-1, 9, 50, 120 and 200, plus the River Repair Shop and two French chapters. Lines without English should fall below 1% (from 2–8%). Visually check ch-9 pair 142.

#### R2 + R4 — French English colours and line placement *(owner report #1)*
- **Files:** `reader.js` (lookup span emission ~L459–478; `emitEnglishSlice` ~L351–361; `chunkLine` map ~L618–620).
- **Cause:** chunks with a `lookup` array render the French as one span per word, each with its own category, but the English uses only the parent chunk's category and key. Example: cider handbook ch-1, pair 1. "parfois" is an adverb (yellow) but its English "sometimes fits" is coloured as a verb (red).

  The same mismatch causes three other problems:
  - category toggles and "hide mastered" (`data-hanzi`) don't match single French words;
  - all lookup spans share one `data-uid`, so a wrapped phrase records only its last line;
  - its English therefore all lands there (R4: ch-1 pair 39, "pourquoi elle convient au | cidre").
- **Fix:**
  - Inside the parent chunk's located English span, find each `lookup[i].english` on word boundaries.
  - Record coverage per (chunk, word). Emit `data-cat` and `data-hanzi` from the lookup word, falling back to the parent where a word isn't found.
  - Give each lookup word its own line entry: the first line a phrase appears on, or per word.
- **Acceptance:**
  - Cider ch-1 pair 1: "sometimes" is yellow and "fits" is red.
  - Hiding Adverbs hides "sometimes" only.
  - A saved, mastered single French word fades in the English.
  - Pair 39 has English on both lines.

#### R5 — short English glosses coloured inside other words
- **Files:** `reader.js` `buildEnglishCoverage` (exact step ~L259–270).
- **Cause:** the exact match uses `indexOf` with no word boundary, so "in" matches inside "spring" and "he" inside "When". This affects 18% of Embers pairs.
- **Fix:** reuse the boundary check from `findChunkPositions`, and ideally merge the two English matchers so they agree.

#### L1 — partly right typed answers accepted
- **Files:** `app/js/vault.js` `gradeType` (~L670–695).
- **Cause:** spaces are stripped, then the check is `includes` in both directions with no minimum length or word boundary. Confirmed results:
  - "a", "se" and "yan" are accepted for 颜色;
  - "o" is accepted for "colour";
  - "not to run" is accepted for 跑 "to run".
- **Fix:**
  - **Pinyin:** an exact match after removing tones and spaces. Accept "v" for ü.
  - **English:** split senses on `;`/`,`, then compare on whole words after removing a leading "to/a/an/the". Allow a near miss (edit distance ≤1 for words of 5+ letters). Never accept a plain substring.
- **Acceptance:** a unit-style table of the cases above, plus normal correct answers, all behaving as expected.

#### L2 — Mastered in one sitting
- **Files:** `vault.js` (`recordAttempt` ~L52–59, quiz length ~L395–433).
- **Cause:** fixed-length quizzes draw with replacement, and every answer counts towards the 20-attempt window.
- **Fix:**
  - Count at most one attempt per item per quiz session. Further repeats in the same session don't change mastery.
  - Cap fixed lengths at the pool size, or make them loop "all once".
- **Acceptance:** with one saved word, a 30-question quiz moves it by at most one attempt.

#### L3 — a second correct option in multiple choice
- **Files:** `vault.js` `renderChoices` (~L612–619).
- **Fix:** exclude options with the same English (lower-cased, trimmed) or the same word ignoring case. `chapterquiz.js:97` already does the English half.

#### L8 — fill-in blanks the wrong spot
- **Files:** `vault.js` `blankOut` (~L502–507); `chapterquiz.js:116`.
- **Fix:**
  - Store the word's character offset in `context` when saving. French lookups already carry start/end; Chinese chunk positions are known in the reader.
  - Fall back to word-boundary matching for Latin script.
  - Skip fill-in when the word occurs more than once in the sentence.

#### D3 — app update can mix old and new files, or break offline
- **Files:** `app/sw.js` (install ~L42–65, fetch ~L105).
- **Fix:**
  - Install with `cache.addAll(SHELL_FILES.map((u) => new Request(u, { cache: "reload" })))`, so the browser's HTTP cache is bypassed and any failure aborts install, keeping the old version.
  - Only delete old shell caches after a successful install.
  - The fetch fallback `.catch(() => cached)` currently returns `undefined`; return a proper offline response instead.

#### D4 — Listen keeps all decoded audio in memory
- **Files:** `app/js/speech.js` (`_bufferCache` ~L109, ~L192–206).
- **Fix:** replace it with an LRU of about 24 decoded buffers. The MP3 bytes stay in the Cache API.

#### D11 — vendor files missing offline after updates
- **Fix:** add `vendor/hanzi-writer.min.js`, `vendor/pinyin-pro.js` and `icons/icon-180.png` to `SHELL_FILES`.

#### C1 + C3 — remove Treasure Island and The Left Hand of Darkness

- **Steps:**

  2. Make sure the app copes with a downloaded book that has disappeared from the catalogue. It should keep working offline, with an option to remove it (ties in with D10).
- **Git history:** purging Left Hand from history needs a force-push. **Ask the owner first**; don't do it unprompted.

## 6. Verification helpers

**Orphan-line counter (R1, R2, R4, C2).** Run it in the browser console on the local app at 375px. It loads chapters straight from `content/` into IndexedDB and opens each one:

```js
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));
const dbm = await import("/app/js/db.js");
await dbm.updateSettings({ showEnglish: true, readerScript: "pinyin", hideMastered: false });
const lib = await (await fetch("/content/library.json", { cache: "no-store" })).json();
async function orphanRate(book, chId) {
  const meta = lib.books.find((b) => b.id === book).chapters.find((c) => c.id === chId);
  const json = await (await fetch("/content/" + meta.url)).json();
  await dbm.putChapter(book, chId, json);
  window.dispatchEvent(new CustomEvent("nav:reader", { detail: { bookId: book, chapterId: chId } }));
  await sleep(1200 + json.pairs.length * 4);
  let blocks = 0, orphans = 0;
  for (const b of document.querySelectorAll("#reader-pages .reader-block")) {
    blocks++;
    const t = b.querySelector("p.target")?.textContent || "", e = b.querySelector("p.english")?.textContent || "";
    if (/\p{L}/u.test(t) && !/\p{L}/u.test(e)) orphans++;
  }
  return { book, chId, blocks, orphans, pct: +(100 * orphans / blocks).toFixed(1) };
}
// e.g. await orphanRate("embers-beneath-the-mountains", "ch-9")
```
